# Example Claim Mapping: VAL-04 Gateway Observability

## Target claim

“The Gateway produced structured observability evidence linking application-level commands with serial-interface behavior during a controlled validation window.”

## Required evidence

1. `actions.csv` from the Gateway application layer
2. `telemetry.csv` from the Gateway telemetry pipeline
3. `serial_trace.csv` from the eBPF/BCC trace tool
4. `gateway_ebpf_correlation.md` generated by the correlation script
5. Screenshot of the Gateway dashboard during the test window

## Safe thesis wording

- “The collected logs support correlation between the user’s START command and nearby `/dev/ttyUSB0` write activity.”
- “During the observed test window, Gateway logs, telemetry rows, and eBPF metadata provided a multi-layer record of serial-interface behavior.”
- “The result supports VAL-04 within the tested configuration.”

## Unsafe wording to avoid

- “The eBPF script captures every serial event.”
- “The system provides complete visibility.”
- “The Gateway guarantees detection of all unauthorized writes.”

## Limitations to record

- fd-to-path resolution is best effort.
- Perf buffers may drop events under load.
- This is metadata-level observability, not full payload inspection.
- Correlation is timestamp-based and bounded by the test window.
