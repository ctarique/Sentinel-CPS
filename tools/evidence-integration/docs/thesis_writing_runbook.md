# Thesis Writing Runbook

Use this after every lab session or major at-home build session.

## Step 1: Ingest evidence

Copy all new photos, videos, CSV logs, terminal logs, screenshots, traces, and reports into the private OneDrive evidence folder.

## Step 2: Assign evidence IDs

Add each file to the master evidence index. Use stable evidence IDs such as:

- EVID-VAL01-001
- EVID-VAL03-001
- EVID-VAL04-001
- EVID-VAL05-001

## Step 3: Map evidence to claims

Open the claim-evidence traceability sheet. For each claim, identify the evidence file that supports it and the limitations that must be stated.

## Step 4: Draft immediately

Write 1-2 thesis paragraphs while the test is still fresh. Use this structure:

1. What was tested.
2. How the test was executed.
3. What evidence was collected.
4. What the evidence supports.
5. What limitation remains.

## Step 5: Update figures and tables

Add useful screenshots, CSV summaries, and diagrams to the figure/table plan. Mark whether each item is public, redacted, or private only.

## Step 6: Record failures honestly

If a test fails, write it down. Failed tests can still support Chapter 6 limitations and future work.

## Step 7: Keep GitHub sanitized

Before committing anything to the public repository, verify it against `public_private_boundary.md`.

## Step 8: Weekly writing checkpoint

At the end of the week, update the weekly thesis progress log. Record what was built, what evidence was collected, what was written, what is blocked, and what the next lab tasks are.
