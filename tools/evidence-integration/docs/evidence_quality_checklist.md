# Evidence Quality Checklist

Before using evidence in the thesis, confirm the following.

## File quality

- [ ] Filename includes a date or timestamp.
- [ ] File is stored in the correct private OneDrive VAL folder.
- [ ] File type is appropriate: CSV for data, TXT/MD for terminal logs, PNG/JPG for screenshots/photos, MP4/MOV for videos.
- [ ] CSV files include headers.
- [ ] Screenshots and videos are readable.
- [ ] Terminal logs include enough command context to interpret the output.

## Traceability

- [ ] Evidence has a unique evidence ID.
- [ ] Evidence is listed in the master evidence index.
- [ ] Evidence maps to at least one validation target.
- [ ] Evidence maps to at least one requirement or research question.
- [ ] Evidence supports a specific thesis claim.
- [ ] Limitations or caveats are recorded.

## Privacy and safety

- [ ] No private keys are included.
- [ ] No full `authorized_keys` content is included in public material.
- [ ] IP addresses, MAC addresses, hostnames, usernames, and internal network details are removed from public copies.
- [ ] Lab photos/videos are reviewed for faces, IDs, whiteboards, hostnames, and restricted equipment.
- [ ] Raw and sanitized versions are stored separately.

## Thesis readiness

- [ ] Evidence has an advisor-readable explanation.
- [ ] Evidence supports the claim without requiring speculation.
- [ ] The claim avoids absolute terms like “guarantees,” “complete,” or “unbypassable.”
- [ ] Failed or partial results are documented honestly.
